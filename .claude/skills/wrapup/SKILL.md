# /wrapup — 会话收尾

每次会话结束前调用。不只是总结，更要**复盘错误 + 提取可复用资产**。

## 运行方式

```
/wrapup
```

---

## Step 1: 代码资产盘点
- `git diff --stat` + `git status -s` 查看改动
- 检查临时调试代码残留
- 检查硬编码数值（应放 `config.js`）
- 检查未使用的实验产物（是否应删除或标注）

## Step 2: 文档同步
- 改了什么机制 → 更新 `docs/项目规划/游戏设计.md`
- 改了什么配置 → 确认 `config.js` 注释充分
- 新增踩坑 → 写入 `.claude/rules/pitfalls.md`
- 新增命令/脚本 → 更新 `CLAUDE.md`

## Step 3: 未修复 bug 登记
- 写入 `docs/项目进展.md`「已知问题」段
- 格式：序号 + 描述 + 发现日期

## Step 4: 清理
- `find . -name "__pycache__" -type d -exec rm -rf {} + 2>/dev/null`
- 删过期 plan 文件
- 检查是否有应入 `.gitignore` 的新文件

## Step 5: Git 收尾
- 项目文件 → war-danmaku 仓库
- 知识库文件 → 知识库仓库
- Memory 文件确认索引已更新

---

## Step 6: 复盘与进化（必须执行，不可跳过）

> Hermes Agent 核心思路：每次完成任务后，自动识别可复用模式 → 生成/更新 Skill → 下次更强。

### 6.1 错误复盘

回顾本轮会话，回答：

```
本轮犯了什么错？
  1. ...
  2. ...

哪些是流程问题（改 SKILL/Hook 能防住）？
  - ...

哪些是知识问题（改 Memory/pitfalls 能防住）？
  - ...
```

### 6.2 模式识别

```
本轮有没有重复 ≥3 次的操作？ → 值得做成 Skill
本轮有没有花了 5+ 步才解决的复杂任务？ → 值得做成 Agent
本轮有没有用户纠正过的错误做法？ → 值得写入 Memory
```

### 6.3 资产审视

逐个回答以下问题：

| 审视维度 | 具体问题 |
|----------|---------|
| **Hook** | 有没有能自动拦住的错误？（如 `.catch(()=>{})` 已有） |
| **Skill** | 现有 skill 有没有过时的？有没有该有但缺失的？ |
| **Agent** | 有没有值得独立出来做 subagent 的流程？ |
| **CLAUDE.md** | 有没有规则过时、缺失或不准确？ |
| **Memory** | 本轮有没有值得持久化的事实？ |
| **pitfalls** | 踩了什么新坑？ |

### 6.4 执行

对 6.3 中每个"是"的回答，**当场创建/更新对应资产**，不留给下次会话。

### 6.5 递归提炼

完成 6.4 后，再问一次：**"刚才提炼资产的过程本身，有没有值得改进的地方？"**

有 → 更新本 SKILL。没有 → 结束。
